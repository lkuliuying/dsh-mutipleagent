## 三、复核后否决的条目（⑩）

体检时用正则搜索 `web/`，没有找到 `OfficeGrid`、`OFFICE_AGENT_BADGES`、`new Office(` 的引用，于是把 `public/vendor/office.js` 判为死代码。复核发现引用是间接的：

- `vendor/office3d.js:68`：`export class Office3D extends window.Office`
- `vendor/office3d.js:32`：`new window.OfficeGrid(def.W, def.D)`

两个符号都由 `public/vendor/office.js` 定义，`public/index.html:56` 与 `public/demo.html:61` 负责加载它。`src/codex.js` 同样不是死代码——standalone 入口通过 `new CodexWatcher()` 使用它。

因此本条不删代码，只把 `vendor/office3d.js` 文件头那句"bundled into public/office3d.js"的过时注释改成了实际情况（与 three.js 一起打进 `public/app.js` 与 `public/demo.js` 的共享 chunk）。这条留在表里，是因为它说明"体检结论也要复核"。

## 五、顺带修掉的真实缺陷

改 `/api/health` 时暴露出一个线上会踩到的 bug：演示模式下该接口返回 500。

- 现象：`GET /api/health` → `{"error":"办公室暂时无法读取数据，请重新连接"}`
- 根因：基类 `CodexWatcher.status(s, state, at)` 是写 Agent 状态的方法，我给 `HarnessWatcher` 新加的 `status()` 与之重名。`src/server.js` 用 `typeof watcher.status === 'function'` 判断后无参调用，落到 `DemoWatcher` 的基类实现上，`s` 为 `undefined` → `TypeError: Cannot set properties of undefined (setting 'status')`
- 修复：`HarnessWatcher.metrics()` 改名，调用点同步；新增两条回归用例锁死行为

第二个是点击搜索结果的偶发失效，直到 CI 上稳定复现才被当成 bug：

- 现象：CI 的浏览器验收里 `tests/plugin-browser.cjs:249` 点 `.search-result` 一直超时，日志是 `element was detached from the DOM, retrying`
- 根因：快照每秒推送一次，`render()` 每次都调 `search()`，而 `search()` 无条件 `results.replaceChildren()` 重建整个列表——正在点击的按钮被摘掉，真人用户表现为"点一下没反应、键盘焦点跳回第一项"
- 修复：按（查询词、语言、命中集合）算签名，签名不变只刷新高亮索引，不重建 DOM（`web/live-office.js`、`web/demo.js`）；本地连跑 3 次浏览器验收稳定通过

同一类问题在修完搜索后又在"模式"下拉上暴露出来（CI 报 `frame.waitForURL: Timeout 30000ms`，点"演示会话"没反应）：

- 根因：`render()` 在每次快照刷新时都重建下拉选项节点，展开的列表被整体替换
- 修复：`web/office-controls.js` 的 `render()` 也按（查询词、语言、当前值、选项集合）算签名，未变化只更新高亮与可见性；连跑 3 次 `npm run test:plugin:ui` 均 11s 通过

## 五之二、首次发版时踩到的两个 CI 问题

本地全绿、推上去就红，两次都值得记下来——它们说明"只在 Windows 上跑过"是不够的。

1. **`npm ci` 直接 500**：`package-lock.json` 里 90 条 `resolved` 被本机镜像写成了 `registry.npmmirror.com`，GitHub 托管机访问该镜像时返回
   `500 Internal Server Error - GET https://registry.npmmirror.com/yocto-queue/-/yocto-queue-0.1.0.tgz - [ER_NO_SUCH_TABLE]`。
   处理：把 `resolved` 统一回 `registry.npmjs.org`，并加仓库级 `.npmrc` 固定官方源，避免下次本地安装又把锁文件改回镜像。
2. **7 个用例在 Linux 上失败**：报错是 `The input did not match the regular expression /未命名会话.*时间未记录.*33333333/`，实际输出却是
   `Untitled session · Time not recorded · 33333333`。根因是 Node 21+ 自带 `navigator.language`（跟随系统 `LANG`），i18n 据此判断默认语言，
   于是同一份代码在中文 Windows 上默认中文、在英文 Linux 上默认英文。
   处理：只有浏览器（`window` 存在）才读 `navigator.language`，Node 下固定中文；UI 用例显式 `locale: 'zh-CN'`；补 4 条 i18n 回归测试（含"没有 window 时默认中文"）。
